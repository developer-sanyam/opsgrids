# Engage Slice 1 — Sending Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An organisation can connect its own email provider, add a sending domain, create named
senders, and prove the setup works with a test send — after which the domain and sender are usable
by everything later slices build.

**Architecture:** Three new tables in the existing `notification` schema (`email_connection`,
`email_domain`, `sender`), reachable through a new `engage` product surface served by
`notification-service`. Writes go through `app/services.py` with audit rows and outbox events;
reads through `app/selectors.py` with `ctx.apply()`. Credentials are sealed with
`platform_core.pii.seal` and never returned by any API. A sender is unusable until a real test send
sets `verified_at`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2 (`Mapped`/`mapped_column`), Alembic, Pydantic v2,
pytest, `aiosmtplib` (already a dependency of notification-service), `dnspython` (new).

**Spec:** `docs/superpowers/specs/2026-09-21-engage-email-platform-design.md`

## Global Constraints

- Every tenant table carries `organization_id` and inherits `TenantBase`; every query filters on it.
- The tenant GUC is transaction-local — `set_config('app.organization_id', …, true)`. Never per-connection.
- No cross-schema foreign keys. The only legal FK is within the `notification` schema.
- Enqueue background work only after commit, via the outbox. Never inline.
- Secrets at rest go through `platform_core.pii.seal` / `unseal`. **No route ever returns a sealed value, masked or otherwise.**
- Every route declares a permission from `services/notification/app/catalogue.py`. Every endpoint gets a negative-authz test (403 for a caller without the permission).
- `import app` is ambiguous across services — run tests from **inside** `services/notification`.
- Money, where it appears, is integer minor units. Not relevant to this slice.
- Ruff and mypy must pass: `uv run ruff check services/notification` and `cd services/notification && uv run mypy app`.
- Do **not** hand-edit `libs/contracts/permissions/*.json` or `libs/contracts/openapi/*.json` — they are generated by `make openapi`.

```python
class EmailConnection(Base, TenantBase):
    """How one organization sends email.

    Deliberately not a row in `provider_accounts`. That table's only unique constraint is
    `phone_number_id` — Meta's webhook routing key, globally unique on purpose — and its
    WhatsApp columns are NOT NULL. Email has no routing key of that kind and needs transport
    settings that table has no room for, so borrowing it would mean weakening a constraint
    WhatsApp depends on in order to reuse three columns.

    `secret_enc` is an app password or an API key, sealed like any other secret at rest. No
    route returns it, not even masked: a masked secret is still a secret with a hint attached.
    """

    __tablename__ = "email_connections"

    #: google | microsoft | smtp | platform. The customer picks a name, not a port — the
    #: transport settings are derived from this (see `domain.transport_for`).
    kind: Mapped[str] = mapped_column(String(20), nullable=False)

    host: Mapped[str] = mapped_column(String(255), nullable=False, default="")
    port: Mapped[int] = mapped_column(Integer, nullable=False, default=587)
    use_tls: Mapped[bool] = mapped_column(Boolean, nullable=False, default=True)
    username: Mapped[str] = mapped_column(String(255), nullable=False, default="")
    secret_enc: Mapped[bytes | None] = mapped_column(LargeBinary)

    #: What this connection can be asked to send in a day. Derived from `kind` at creation and
    #: then editable, because a customer who raises their provider quota should be able to say so.
    daily_cap: Mapped[int] = mapped_column(Integer, nullable=False, default=2000)

    #: connected | disconnected
    status: Mapped[str] = mapped_column(String(20), nullable=False, default="connected")

    __table_args__ = (
        # One connection per organization for now. A second would make "which one sent this"
        # ambiguous before anything records the answer.
        UniqueConstraint("organization_id", name="uq_email_connection_org"),
    )


class EmailDomain(Base, TenantBase):
    """A domain an organization may send from, and the state of its DNS.

    `records` is the generated record set — SPF, DKIM, DMARC, return-path, tracking — stored so
    the setup screen can show the same values it showed yesterday rather than regenerating a
    DKIM selector the customer has already pasted into their registrar.
    """

    __tablename__ = "email_domains"

    domain: Mapped[str] = mapped_column(String(253), nullable=False)
    #: pending | verified | failed. Derived from `records` by `domain.fold_domain_status`.
    status: Mapped[str] = mapped_column(String(20), nullable=False, default="pending")
    records: Mapped[list[dict[str, Any]]] = mapped_column(JSONB, nullable=False, default=list)
    last_checked_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))

    __table_args__ = (
        UniqueConstraint("organization_id", "domain", name="uq_email_domain_org_domain"),
        Index("ix_email_domains_org_status", "organization_id", "status"),
    )


class Sender(Base, TenantBase):
    """A named identity mail goes out as: Sales, Support, Accounts.

    `verified_at` is set by one thing only — a test send that actually reached the provider.
    Until then `usable` is False and a campaign may not select this sender. That gate is the
    whole point of the setup wizard: it converts "we filled in a form" into "mail left the
    building".
    """

    __tablename__ = "senders"

    domain_id: Mapped[uuid.UUID] = mapped_column(PGUUID(as_uuid=True), nullable=False)
    name: Mapped[str] = mapped_column(String(120), nullable=False)
    address: Mapped[str] = mapped_column(String(254), nullable=False)
    reply_to: Mapped[str] = mapped_column(String(254), nullable=False, default="")
    signature: Mapped[str] = mapped_column(Text, nullable=False, default="")
    department: Mapped[str] = mapped_column(String(80), nullable=False, default="")
    verified_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))

    __table_args__ = (
        UniqueConstraint("organization_id", "address", name="uq_sender_org_address"),
        Index("ix_senders_org_domain", "organization_id", "domain_id"),
    )

    @property
    def usable(self) -> bool:
        """Whether a campaign may send as this sender."""
        return self.verified_at is not None
```

```python
@dataclass(frozen=True)
class TransportSettings:
    """What a connection kind means in SMTP terms.

    The customer chooses "Google Workspace", not a port. Everything below that choice is derived
    here so the wizard never has to ask, and so a provider changing its submission host is one
    edit in one place.
    """

    host: str
    port: int
    use_tls: bool
    daily_cap: int


#: Caps are the provider's published external-recipient limits, not ours. They exist so a campaign
#: can be refused before it burns a mailbox rather than after — a suspended Workspace account is a
#: worse outcome than a rejected campaign.
_KINDS: dict[str, TransportSettings] = {
    "google": TransportSettings("smtp.gmail.com", 587, True, 2_000),
    "microsoft": TransportSettings("smtp.office365.com", 587, True, 10_000),
}


def transport_for(kind: str, username: str) -> TransportSettings:
    """Derive transport settings from the connection kind the customer chose."""
    if kind in _KINDS:
        return _KINDS[kind]
    if kind == "smtp":
        # Host and port come from the customer; this is the shape, filled in by the caller.
        return TransportSettings("", 587, True, 2_000)
    if kind == "platform":
        return TransportSettings("", 587, True, 50_000)
    raise ValueError(f"Unknown connection kind {kind!r}")


def dns_records_for(
    domain_name: str, dkim_selector: str, tracking_host: str
) -> list[dict[str, Any]]:
    """The record set an organization must publish to send as `domain_name`.

    DMARC is `required=False` deliberately. It is the right thing to publish and the setup screen
    recommends it, but a domain that has not got there yet still sends — refusing would block a
    customer on a policy decision their security team may still be making.
    """
    return [
        {
            "kind": "spf",
            "type": "TXT",
            "host": domain_name,
            "value": "v=spf1 include:_spf.opsgrids.com ~all",
            "required": True,
            "verified": False,
        },
        {
            "kind": "dkim",
            "type": "TXT",
            "host": f"{dkim_selector}._domainkey.{domain_name}",
            "value": "",  # filled with the generated public key at creation
            "required": True,
            "verified": False,
        },
        {
            "kind": "dmarc",
            "type": "TXT",
            "host": f"_dmarc.{domain_name}",
            "value": "v=DMARC1; p=none; rua=mailto:dmarc@opsgrids.com",
            "required": False,
            "verified": False,
        },
        {
            "kind": "return_path",
            "type": "CNAME",
            "host": f"bounce.{domain_name}",
            "value": "bounce.opsgrids.com",
            "required": True,
            "verified": False,
        },
        {
            "kind": "tracking",
            "type": "CNAME",
            "host": tracking_host,
            "value": "track.opsgrids.com",
            "required": True,
            "verified": False,
        },
    ]


def fold_domain_status(records: list[dict[str, Any]]) -> str:
    """`verified` when every required record passes; otherwise `pending`."""
    required = [r for r in records if r.get("required")]
    if required and all(r.get("verified") for r in required):
        return "verified"
    return "pending"
```

```python
"""The one place this service performs a DNS lookup.

`app/domain.py` stays pure so the record set and the verification rules can be tested without a
network; everything that can fail because the internet is having a bad day lives here, behind an
injectable resolver.
"""

from __future__ import annotations

from typing import Any, Protocol


class Resolver(Protocol):
    async def resolve(self, host: str, rtype: str) -> list[str]: ...


async def check_records(
    records: list[dict[str, Any]], *, resolver: Resolver | None = None
) -> list[dict[str, Any]]:
    """Return a copy of `records` with `verified` set from what DNS actually publishes.

    A record verifies when its expected value appears among the answers — `in`, not equality,
    because resolvers split long TXT strings and registrars append their own.
    """
    r = resolver or _default_resolver()
    out: list[dict[str, Any]] = []
    for record in records:
        answers = await r.resolve(record["host"], record["type"])
        expected = (record.get("value") or "").strip()
        verified = bool(expected) and any(expected in a for a in answers)
        out.append({**record, "verified": verified})
    return out
```

Then add `_default_resolver()` wrapping `dns.asyncresolver`, returning answers as strings. Keep it
small — it is the only untested line, and it is untested because it is the network.

## Self-Review

**Spec coverage.** This plan covers spec §2 (setup wizard, domains, DNS), §3 (multiple senders),
§16 (permissions, via the Engage catalogue and role templates) and the parts of §18 that are
per-connection limits (`daily_cap`). It deliberately does **not** cover §4–§15 and §17, §19–§20 —
those are Slices 2–4 and later phases, each of which gets its own plan.

**Known gaps deferred by design, not overlooked:**
- The wizard UI (spec §21) is backend-only here; the frontend is a separate plan once the API is stable.
- `platform` connection kind is modelled but its infrastructure (a real MTA) does not exist. Task 3
  gives it settings; nothing can select it until that infrastructure is decided. This is recorded
  rather than silently working.
- DKIM **key generation** is not in Task 3 — `dns_records_for` leaves the DKIM value empty for the
  caller to fill. Generating and storing the keypair belongs with `create_domain` in Task 5 and must
  be written there; if it is not, the DKIM record can never verify.

**Type consistency.** `TransportSettings` is used with the same four fields in Tasks 3 and 5.
`check_records` has the same signature in Task 4's test and its implementation. `Sender.usable`
is defined in Task 2 and relied on in Task 5.
